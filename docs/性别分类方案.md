# 性别分类方案选型（二次元群聊场景）

> 背景：根据群内发言（文本 + 图片/表情包）推测发言人的生物性别，标签按 QQ 号标定。
> 难点：① 二次元群性别比例严重失衡（男多女少）；② 同一 QQ 号的多条消息高度相关，必须**按人**划分数据集；③ 图片/表情包携带性别信号。

## 0. 结论速览

| 路线 | 说明 | 适用阶段 |
|---|---|---|
| **TF-IDF + 线性模型**（scikit-learn） | 加 `class_weight='balanced'` 的快速基线 | 起步验证数据可用性 |
| **中文预训练模型微调**（Erlangshen-Roberta / chinese-roberta-wwm） | 主力方案；加权交叉熵或 Focal Loss 处理不平衡 | 正式训练 |
| **LLM few-shot 打标**（Qwen 等） | 少量标注 → 大模型批量打伪标签 → 自训练/蒸馏 | 标注不足时扩充 |
| **多模态增强**（Chinese-CLIP / Qwen2.5-VL） | 图片与表情包向量/描述并入模型 | 文本模型稳定后叠加 |
| **用户级 Group 划分 + 分层抽样** | 同一 QQ 号只出现在 train 或 val 一侧 | 全程必须 |

## 1. 为什么没有"现成的聊天性别分类器"

GitHub 上不存在开箱即用的"中文聊天性别分类"高星项目（多为姓名性别预测、PAN 作者画像竞赛代码、英文推特性别分类等）。因为**标签高度依赖私有数据**——你的群友性别只有你知道。所以正确姿势是：**通用中文预训练模型 + 你的私有标注数据微调**。方案选型如下。

## 2. 文本模型三条路线

### 2.1 快速基线：TF-IDF + 线性模型
- 工具：[scikit-learn](https://github.com/scikit-learn/scikit-learn)（⭐67k，持续维护）
- 做法：`TfidfVectorizer(ngram_range=(1,2), min_df=5, max_features=200000)` + `LogisticRegression(class_weight='balanced')`
- 优点：秒级训练、可解释（权重最高的词就是"性别词"）、几十万条无压力；
- 缺点：上限低，但**是必做的第一步**——先确认"文本里到底有没有性别信号"。

### 2.2 主力：中文预训练模型微调（推荐）
- 基座模型：
  - [IDEA-CCNL/Fengshenbang-LM](https://github.com/IDEA-CCNL/Fengshenbang-LM)（⭐4.1k，活跃）——封神榜体系，`Erlangshen-Roberta-110M` 系列有完整分类微调示例；
  - 或 HuggingFace `hfl/chinese-roberta-wwm-ext`（通用稳妥）；
- 框架：[huggingface/transformers](https://github.com/huggingface/transformers)（⭐164k）`AutoModelForSequenceClassification` + Trainer；
- 不平衡处理（损失层）：
  - 加权交叉熵：`class_weights = total / (n_classes * class_counts)`；
  - [Focal Loss](https://github.com/AdeelH/pytorch-multi-class-focal-loss)（或 [CoinCheung/pytorch-loss](https://github.com/CoinCheung/pytorch-loss)，⭐2.3k）：让模型聚焦难分样本，二次元群"男装女/萌妹发言"这类难例正适合；
- 评估指标：**不要用 accuracy**（95% 男群，全猜男就 95%）。用 **macro-F1 / PR-AUC / 少数类（女）recall**；训练后做**阈值校准**（threshold moving），在"女性 recall vs 精确率"之间选业务可接受的点。

### 2.3 LLM few-shot / 伪标签扩充（标注不足时）
- 用 Qwen 等大模型对未标注消息打性别伪标签（prompt：给 10 条已标注样例 + 待判文本）；
- 只保留高置信度样本 → 加入训练集（自训练），或用大模型当教师蒸馏小模型；
- 注意：大模型对"二次元语境的性别"同样有偏见，伪标签需抽检。

### 2.4 训练脚本（已实现，`train/` 目录）

| 脚本 | 功能 |
|---|---|
| `baseline_tfidf.py` | TF-IDF+LR 基线：`--mode message`（逐条+用户级聚合评估）/ `--mode user`（按人聚合文档分类）；输出性别化词表与错分用户 CSV |
| `train_bert.py` | 中文 RoBERTa 微调：Focal Loss、label smoothing、`--user-weight` 用户均衡、`--user-doc` 用户级文档建模、`--adv-user` GRL 对抗、昵称/上下文特征、用户级评估+阈值校准+错分导出 |
| `predict.py` | 对 infer.jsonl 批量预测，按 QQ 号聚合输出 `user_id, n_messages, prob_female, predicted` CSV |

**关于"对抗网络"的落地**（对应"男生卖萌极其夸张、平均解决不掉"的观察）：
- GAN 式**生成**（补少数类样本）对中文对话不实用（文本 GAN 不稳定、质量差）；
- 真正成立的是**对抗式去风格化**：`--adv-user` 加一个"用户身份判别器"（GRL 梯度反转），强迫编码器学会"能预测性别、但猜不出是谁在说"的表示，从而剥离个人夸张风格指纹，只留性别泛化特征（DANN 标准组件）；
- 配合 Focal Loss（聚焦风格反向难例）+ `--user-doc`（整体风格建模）+ 错分用户人工复核，比"简单平均"稳健得多。实现细节见 `train/README.md`。

## 3. 类别不平衡策略（分层组合拳）

| 层 | 手段 |
|---|---|
| 数据层 | 用户级**欠采样**多数类（按人抽，防止话痨刷屏）；少数类**过采样**：`--oversample dup/eda/ctx`（复制/字符扰动/上下文窗口变体，见 train/README.md 的 GAN 取舍说明）；`--balance` 导出侧欠采样 |
| 损失层 | 加权 CE / Focal Loss |
| 划分层 | **按 QQ 号 Group 划分** + 每 fold 保持全局性别比例（分层） |
| 评估层 | macro-F1 / PR-AUC / 少数类 recall，不做 accuracy 优化 |
| 决策层 | 阈值校准（threshold moving） |

> ⚠️ 关键坑：**同一个人不能既在训练集又在验证集**。你的模型要能泛化到"新出现的人"，如果按消息随机切分，模型会记住个人口头禅（"喵~"、"咱就是说"）而虚假高分——这就是"给 QQ 号标定性别用于划分训练集"的意义。

### 3.1 标签噪声与"风格错位"（男声女气 / 女声狂野）

**问题本质**：生物性别 ≠ 语言风格。二次元群里"男装女""狂野女汉子"会让单条消息与标签矛盾，这些样本对模型而言是**标签噪声**（label noise）。对策（按优先级）：

| 手段 | 说明 | 本项目支持 |
|---|---|---|
| **用户级聚合建模** | 一个人的标签基于其几百条消息的整体风格，单条错位被平均掉——这是对抗该噪声最有效的手段 | `--split-by-user` + 按人聚合训练 |
| **标注置信度分级** | 只把"有把握"的人标 high；风格明显错位/拿不准的人标 low 或干脆不标（宁缺毋滥） | `label.js --confidence`；`import-labels.js --confidence`；导出 `--min-confidence` |
| **损失层** | label smoothing（软化硬标签，容忍错位样本）+ Focal Loss（聚焦难例） | 训练脚本实现（基线脚本预留） |
| **训练后错误分析** | 找"高置信错分"的用户人工复核：可能是标签错（他确实女气）→ 改标 low/移出训练集，而不是硬让模型记住 | `export-context.js --format readable` 通读该人发言复核 |
| **按人均衡采样** | 每个用户的样本数均衡，避免个别"风格极端者"主导梯度 | `--max-per-user` / `--balance` |

**边界认知**：模型输出的本质是"该人发言风格更接近哪一类的统计似然"。对风格与生物性别严重错位的人，任何模型都会错——评估时按**用户级**指标看（对 80% 风格典型的人预测准即可用），不追求单条消息的准确率。

## 4. 图片与表情包怎么用

图片/表情包不直接标性别，而是作为**发言人的风格特征**，三个渐进层次：

| 层次 | 做法 | 工具 |
|---|---|---|
| L1 统计特征 | 每用户表情包使用频次、类型分布（face/market_face/image）、时段分布 → 拼入文本模型特征 | 本项目 `media_files` 表直接出 |
| L2 图像向量 | 图片/表情包 → 向量，与文本向量拼接或加权融合 | [OFA-Sys/Chinese-CLIP](https://github.com/OFA-Sys/Chinese-CLIP)（⭐6k，中文图文检索） |
| L3 图像描述 | 表情包 → 文本描述（"猫猫委屈表情包"）→ 当文本拼接进输入 | [QwenLM/Qwen2.5-VL](https://github.com/QwenLM/Qwen2.5-VL)（⭐19.8k） |

二次元群的实证经验：表情包选择（猫系/萌系/抽象梗图）与性别相关性较强，**L1 统计特征性价比最高，建议文本模型稳定后优先做 L1**，L2/L3 作为后续增强。

## 5. 数据集划分（本项目实现）

`scripts/export-dataset.js` 已支持：

```bash
# 按 QQ 号分层划分：15% 的用户进验证集，同一人不跨集
node scripts/export-dataset.js --mode train --split-by-user --val-ratio 0.15 --seed 42

# 用户级欠采样平衡多数类
node scripts/export-dataset.js --mode train --split-by-user --balance

# 导出时附带图片路径（训练多模态模型用）
node scripts/export-dataset.js --mode train --split-by-user --include-media
```

产出：
- `train.jsonl` / `val.jsonl`：`{"text":..., "label":"male", "user_id":..., "group_id":..., "images":[...], "before":[...], "after":[...]}`
- 保证：`train 用户 ∩ val 用户 = ∅`，且各 split 内性别比例 ≈ 全局比例。

**上下文拼接**（配合第 7 节）：`--context N` 附加同群前后各 N 条消息（`before`/`after` 数组），`--fold-context` 直接折叠进 `text`（上文+本条+下文换行拼接）。上下文窗口按"到达序"（自增 id 邻域）取，同群保证。

**跨群泛化验证（多群场景必做）**：`--val-groups <群号,...>` 把指定群的标注用户**整体**放进验证集（`import-labels.js` 会按"群聊 NNN"分段记录 label_group）。用它检验模型学的是"性别泛化特征"还是"群内黑话风格"——若两个风格相似的群上跨群指标不崩，说明泛化良好；若崩了，考虑减少群特有词依赖（降 min_df 意义不大，可试 `--no-nickname` 或加 `--adv-user` 去风格化）。

**标注时机与自动化**：
- 标定在**采集后、导出前**人工执行（`label.js --user <QQ> --gender male|female`），可随时补标/改标（覆盖式更新）；
- 已标注用户**之后新采集的消息自动进入训练集**（导出时动态 JOIN，无需重新登记）；
- train 导出自动写 `<out>.meta.json`（标签版本元数据，含 `max_label_updated_at`），训练流水线对比该时间戳判断是否需要重训；
- `label.js` 标注后打印覆盖率；`stats.js` 列出未标注活跃用户（按发言量排序）建议优先标注。

## 6. 推荐实施顺序

1. 采集与标注跑起来（已有框架），先攒 3~5 万条、标注 ≥30 人（男女尽量均衡）；
2. **TF-IDF + LR 基线**看 macro-F1，验证信号存在；
3. **Erlangshen-Roberta / chinese-roberta 微调** + 加权 CE/Focal，按用户 Group 划分评估；
4. 加 **L1 表情包统计特征**（或 CLIP 向量），看是否有提升；
5. 若女性样本仍太少（<10 人），用 **LLM 伪标签**扩充或继续采集目标群；
6. 上线后：用本项目的实时/增量采集持续补充，定期重训。

## 7. 昵称与群名片特征（强信号）

**QQ 全局昵称与群名片是二次元群里最强的单点特征之一**（"小仙女""某酱""御姐""猛男"等自述身份），应纳入模型：

| 特征 | 来源 | 本项目实现 |
|---|---|---|
| 昵称快照（消息时刻） | `messages.nickname` | 导出样本默认带 `nickname` 字段（该消息发出时的昵称） |
| 群名片快照（消息时刻） | `messages.card` | 导出样本默认带 `card` 字段（该群的群名片） |
| 当前最新昵称 | `user_profiles.nickname` | 推理时用；按消息时间更新，回填不会覆盖 |
| 上下文发言人昵称 | `getContext` | `--context N` 时 `before_meta/after_meta` 含发言人昵称/名片；`--fold-context` 每行前缀"昵称: 文本" |

用法建议：

1. **拼接进文本**：`[昵称] [群名片] 发言内容`（或 `--fold-context` 已带昵称前缀）——BERT 系模型直接把昵称当普通文本 token 学即可；
2. **独立特征**：昵称单独过 embedding 与文本向量拼接（昵称短、重复率高，适合查表式特征）；
3. **⚠️ 泄漏警惕**：昵称可能直接包含性别词（"小仙女"），模型可能只学昵称不看发言。这本身是合法信号，但评估泛化性时要做消融——`export-dataset.js --no-nickname` 导出去昵称版本对比，观察对"中性昵称用户"的预测是否仍然有效。

## 8. 上下文依赖与样本形态（重要）

**脱离上下文的单条消息会损失大量性别信号**，二次元群尤其严重：

1. 大量消息是超短句（"哈哈哈""6""蹲蹲""笑死"），单条信息量趋近于零，连起来才有信号；
2. 性别信号常跨消息分布：短句连发节奏、回复/引用的方式与对象、表情包使用频率与搭配；
3. 标签定义在"人"上，单条样本本质是"用一条消息预测一个人的属性"，天然需要聚合。

### 采集层面：保信息，而不是预设窗口

只要消息的**完整内容、时间、顺序、引用关系**都在库里，训练时任何上下文形态都可以事后构造。本项目已做到：

- `messages` 表保留 `time` / `message_seq` / 自增 `id`（到达序），可按人/按群重建完整时序；
- `raw_json` 保留原始事件（含 reply 引用段、图片元数据）；
- `text` 解析保留引用摘要（`「引用:...」`）；
- **上下文快照**：`context.users` 实时跟踪 + `scripts/export-context.js` 回溯导出（readable 格式便于人工标注时通读）。

### 训练层面：三种样本形态（按优先级）

| 形态 | 做法 | 适用 |
|---|---|---|
| **用户级聚合（首选）** | 把一个人的 N 条消息聚合（截断/拼接/取均值向量）为一个样本，标签=该人性别 | 与"按 QQ 号标定"天然对齐，泄漏风险最低 |
| **上下文拼接** | 每条消息拼接群内前后 K 条（或该人自身历史 K 条）再输入 | 保留对话语境，适合短消息群 |
| **单条消息** | 直接一条一判 | 仅作基线/难例分析；短消息需 `min_text_len` 过滤 |

推荐：**训练用"用户级聚合"为主**（Erlangshen-Roberta 输入＝该人最近 128~256 token 的发言拼接），**推理时**对同一人最近 K 条消息分别打分再投票/平均，兼顾上下文与实时性。上下文快照文件（`data/context/`）就是为此准备的样本源。
