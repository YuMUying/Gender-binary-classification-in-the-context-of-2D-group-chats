# 涩情等级标注说明（手动补标用）

> 用途：当新采集的群/私聊样本在本机涩情模型（models/erotic-bert）上表现不佳、或需要人工修正标签时，
> 按本文档标准手动标注。标注结果与 LLM 自动标注（research/erotic_labels.jsonl）合并参与训练。
> 合并规则：同一条消息，人工标注优先于 LLM 标注。

## 一、四级定义（0-3）

| 等级 | 名称 | 定义 | 典型例子（本群真实数据） |
|---|---|---|---|
| 0 | 无 | 无任何涩情/色情/性暗示内容 | 日常聊天、玩梗、讨论游戏动漫 |
| 1 | 轻微 | 暧昧擦边：暗示性双关、卖萌式性玩笑、擦边图描述、明显挑逗但含蓄 | "穿这么少不冷吗"，暗示性表情，涩图分享的铺垫话 |
| 2 | 明显 | 明确色情：露骨词汇、性行为描写、直接要涩图、发露骨涩图说明 | 直接谈性行为、发本子/涩图并评价 |
| 3 | 露骨 | 极端露骨：详细性行为描写、性器官直称、约炮/色情交易 | 对性行为细节的详细描述、露骨性需求表达 |

## 二、判定规则

1. **日常粗口不算涩情**：卧槽、我操、妈的、草（单独使用）→ 一律 0 级。
2. **二次元语境**：提到腿/白丝/泳装/绝对领域等，需结合上下文——单纯讨论/玩梗 → 0 或 1；明确带性挑逗意图 → 1 或 2。
3. **发图场景**：`[图片:...]` 占位符无法看到图内容时，按**文字语境**判定；若文字明确是"发涩图"类（"涩图来了""图在这"等）→ 至少 1 级，视露骨程度 1-2 级。
4. **对话互动**：A 发涩内容、B 回应配合 → 双方都按各自文本判定，不因对方内容连坐。
5. **玩笑 vs 事实**：黄色玩笑（不涉及具体性行为描写）→ 1 级；具体描写 → 2-3 级。拿不准时取较低等级（宁轻勿重）。

## 三、手动标注方式

1. 编辑 `research/erotic_labels.jsonl`，每行：
   `{"id": <messages表行id>, "user_id": <QQ号>, "text": "<消息文本>", "level": 0-3}`
2. `id` 从数据库查询：`SELECT id, text FROM messages WHERE user_id=<QQ号> AND ...`
3. 追加新行即可；训练脚本自动去重（同 id 以文件后出现的为准，人工追加在后 → 人工优先）。
4. 批量操作建议：先把待人工判定条目导出成 CSV，改完后用脚本回写 JSONL。

## 四、新群样本不足时的处理

- 新群若消息量少（如 <500 条），先跑本机模型初判，再人工抽查 **全部 1-3 级** 消息（数量通常不多），修正后合入训练。
- 抽查工具：`research/erotic_inspect.py`（列出某用户/某群的逐条预测与置信度，供人工确认）。
