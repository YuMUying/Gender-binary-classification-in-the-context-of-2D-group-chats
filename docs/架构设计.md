# 架构设计

## 1. 目标

在 PC（或树莓派）上长期运行一个 QQ 数据采集机器人，为**"根据群内发言推测生物性别"的标定器**提供数据：

- **阶段一（一次性）**：对指定群批量拉取大量历史聊天记录，构建初始数据集；
- **阶段二（长期）**：实时监听 + 定期增量同步，持续小批量补充新聊天记录，用于模型维护；
- 数据以**去重、可标注、可导出**的形式持久化，最终产出训练集（已标注性别）与推断集（未标注）的 JSONL/CSV。

> ⚠️ 合规：聊天内容与性别标注均为敏感个人信息，本项目仅供**本人自用**（本人所在的群、或已获同意的群）。请勿对外分发数据集。

## 2. 总体架构

## 3. 采集三模式

| 模式 | 触发 | 数据方向 | 说明 |
|---|---|---|---|
| **live**（实时） | WebSocket `message` 事件，7×24 | 新消息即时入库 | 主通道；服务在线时零丢失 |
| **backfill**（历史回填） | 启动时 / `bulk-collect.js` 手动 | 从最新向前翻页 | 一次性大规模采集；断点续传、限速、去重 |
| **gapfill**（增量补齐） | 定时器（默认 30 分钟） | 从最新向前翻到与库内数据重叠为止 | 补服务离线期间的断档 |
| **context**（上下文快照） | 指定 QQ 号发言时实时触发 / `export-context.js` 回溯 | 该消息前后各 N 条 | 单条消息脱离上下文信息量低，为目标用户保留上下文样本 |

**上下文快照**（`src/context.js`）：配置 `context.users` 后，目标用户每条发言会连同群内前后 `window` 条消息（含发言人）写入 `data/context/<user_id>/context-YYYY-MM-DD.jsonl`（幂等，`context_exports` 表去重）。历史数据可随时用 `scripts/export-context.js --user <QQ号> --format readable` 回溯导出（readable 格式适合人工标注时通读）。

**回填算法**（backfill / gapfill 共用）：

```
anchor = 起始 message_seq（缺省 = 最新）
loop:
  get_group_msg_history(group_id, message_seq=anchor, count=pageSize)
  逐条入库（UNIQUE(message_id) 去重，重复即忽略并计数）
  anchor = 本页最旧 message_seq
  untilSeq 到达 / 无新消息 / 翻页超限 → 停止
  sleep(delayMs)   ← 限速，默认 800ms/页
```

**断点续传**：`sync_state` 表记录每个群的 `oldest_seq`（已抓到的最旧序号），重跑时自动从断点继续，不怕中断。

## 4. 数据库设计（SQLite，`data/qqchat.db`，WAL 模式）

### messages —— 全量消息（唯一事实来源）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | 自增 |
| scene | TEXT | `group` / `private` |
| peer_id | INTEGER | 群号或 QQ 号 |
| message_id | INTEGER | OneBot 全局消息 ID（去重键） |
| message_seq | INTEGER | 会话内序列号（历史消息有；实时为 null） |
| group_name | TEXT | 群名（入库时缓存） |
| user_id | INTEGER | 发送者 QQ 号 |
| nickname / card / role | TEXT | 昵称 / 群名片 / 身份 |
| time | INTEGER | 发送时间（Unix 秒） |
| text | TEXT | CQ 码解析后的纯文本 |
| raw_json | TEXT | 原始事件 JSON（保留完整证据） |
| source | TEXT | `live` / `history` |
| collected_at | INTEGER | 入库时间 |

唯一约束：`UNIQUE(scene, peer_id, message_id)`；索引：`(peer_id, time)`、`(user_id, time)`。

### speaker_labels —— 性别标注（训练标签）

| 字段 | 类型 | 说明 |
|---|---|---|
| user_id | INTEGER PK | 发言人 QQ 号 |
| nickname | TEXT | 冗余昵称（便于辨认） |
| gender | TEXT | `male` / `female` / `unknown` |
| label_source | TEXT | `manual` / `known` |
| updated_at | INTEGER | 更新时间 |

标注方法：`node scripts/label.js --user <QQ号> --gender male|female`（你知道性别的群友逐个标）。

**标注的用途**：标签按 QQ 号挂载，导出训练集时按"发言人"分组划分 train/val（同一 QQ 号不跨集），防止个人口头禅造成数据泄漏——详见 [`docs/性别分类方案.md`](性别分类方案.md)。

### media_files —— 聊天图片 / 表情包（多模态特征）

| 字段 | 类型 | 说明 |
|---|---|---|
| message_id | INTEGER | 关联消息（与 messages.message_id 对应） |
| media_type | TEXT | `image`（聊天图片）/ `market_face`（市场表情包）/ `face`（QQ 基础表情，仅记录） |
| url / file_id | TEXT | 下载地址 / 文件标识（去重键） |
| local_path | TEXT | 下载到本地的路径（`data/media/<群号>/<md5>.<ext>`） |
| status | TEXT | `pending` / `downloaded` / `failed` / `recorded`（无直链仅记录） |

- 下载由 `src/media.js` 串行限速执行（默认 1s/张），URL 失效标 `failed`，调度器自动重试；
- 图片 URL 有有效期，**采集与下载需同步进行**（实时消息即时下载；历史回填可 `--no-media` 跳过）；
- 表情包使用风格是二次元群性别信号的重要来源（见 `docs/性别分类方案.md` 第 4 节 L1 特征）。

### sync_state —— 回填进度

| 字段 | 类型 | 说明 |
|---|---|---|
| scene, peer_id | PK | 会话 |
| oldest_seq | INTEGER | 已抓到的最旧 seq（断点） |
| newest_seq | INTEGER | 已入库的最新 seq |
| last_sync_at | INTEGER | 上次同步时间 |

### context_exports —— 上下文快照去重

记录已写入上下文快照的中心消息 ID（`message_id` 主键），保证同一条消息不重复写文件。

### user_profiles —— 用户档案（昵称/名片追踪）

| 字段 | 类型 | 说明 |
|---|---|---|
| user_id | INTEGER PK | 发言人 QQ 号 |
| nickname | TEXT | **最新 QQ 全局昵称**（按消息时间比较更新，回填旧消息不会覆盖新昵称） |
| first_seen / last_seen | INTEGER | 首次/最后发言时间 |
| message_count | INTEGER | 累计消息数 |

- 每条消息入库时自动 upsert；旧库首次打开自动一次性重建；
- 用途：`label.js --top` 认人、`stats.js` 活跃榜、特征工程（当前昵称）；
- 群名片（card）是**按群、按消息时间**的快照，存在 `messages.card` 里（每群不同、随时间变化），不单独建表。

## 5. 导出格式（供训练使用）

### train.jsonl / val.jsonl（按 QQ 号分层划分）

```bash
# 15% 的"用户"进验证集（同性别组内按用户随机），同一 QQ 号不跨集
node scripts/export-dataset.js --mode train --split-by-user --val-ratio 0.15 --seed 42

# 多数类用户级欠采样（二次元群男女失衡时的平衡手段）
node scripts/export-dataset.js --mode train --split-by-user --balance

# 附带图片路径（多模态训练）
node scripts/export-dataset.js --mode train --split-by-user --include-media

# 附加上下文窗口：每条样本带同群前后 N 条（before/after 数组）
node scripts/export-dataset.js --mode train --split-by-user --context 5

# 上下文折叠进 text（上文 N + 本条 + 下文 N 换行拼接，可直接喂模型）
node scripts/export-dataset.js --mode train --split-by-user --context 5 --fold-context
```

每行一条：
```json
{"text": "今天打球去了", "label": "male", "user_id": 111, "group_id": 222, "time": 1754208000,
 "nickname": "猛男阿强", "card": "群草",
 "before": ["早啊", "早，今天摸鱼吗"], "after": ["没有瓜，只有砖", "哈哈哈哈"],
 "before_meta": [{"user_id":101,"nickname":"小明","card":null}],
 "images": ["data/media/222/ab12cd...jpg"]}
```

- `nickname`（QQ 全局昵称）与 `card`（群名片）为**消息时刻的快照**，是强性别信号；`--no-nickname` 可去掉（消融实验）；
- `--fold-context` 折叠上下文时每行带发言人昵称前缀（`昵称: 文本`），保留"谁说了什么"。

**标签版本元数据**：train 模式自动在训练集旁写出 `<out>.meta.json`（含各性别用户数、消息数、`max_label_updated_at`）。训练流水线记录上次训练时的标签时间戳，对比当前值即可判断"标注有新增/修改 → 需要重训"。

**标注时机**：标定在**采集之后、导出之前**人工执行（`label.js`）。标签存于 `speaker_labels` 表，可随时补标/改标；导出时动态 JOIN，因此**已标注用户之后新采集的消息会自动进入训练集**，无需任何额外操作。`label.js` 标注后即时打印覆盖率，`stats.js` 列出未标注活跃用户建议优先标注。

### infer.jsonl（待预测集）
```json
{"text": "今天打球去了", "user_id": 111, "group_id": 222, "time": 1754208000}
```

### all.csv（全量人工检查）
`time,group_id,group_name,user_id,nickname,card,gender,text`

可选参数：`--min-per-user N`（每人最少条数）、`--max-per-user N`（每人最多条数，均衡类别）。

> 类别不平衡、多模态、模型选型的完整方案见 [`docs/性别分类方案.md`](性别分类方案.md)。

## 7. 采集速率与风控

- 默认 `pageSize=20`、`delayMs=800`（约 25 条/秒理论值，实际受协议端限流），**大量回填时宁可慢**；
- 回填按群**串行**进行，避免高频请求触发腾讯风控；
- 只采集**文本类消息段**（text/at/face 摘要等），图片语音仅留摘要——训练目标是文本；
- 建议用**小号**入群；`ignoreSelf=true` 排除机器人自身消息。

## 8. 常驻运行（Windows）

- 开发调试：双击 `start.bat`；
- 长期常驻：用 [NSSM](https://nssm.cc/) 把 `node src\index.js` 注册为 Windows 服务，开机自启、崩溃自动重启；
- 树莓派：同一套代码直接跑（纯 Node），配 systemd；协议端用 napcat-docker 的 arm64 镜像。
